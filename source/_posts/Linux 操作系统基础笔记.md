## 一、计算机与操作系统概述

### 1.1 计算机的组成

计算机由 **硬件** 和 **软件** 两大部分组成。

- **硬件**：CPU、内存、硬盘、网卡等物理设备
- **软件**：操作系统、应用程序、驱动程序等

### 1.2 什么是操作系统

操作系统（Operating System，OS）是**系统软件**的一种，它的核心作用是：

- 管理硬件资源（CPU调度、内存分配、磁盘读写）
- 为用户和应用程序提供操作接口
- 充当 **用户 ↔ 计算机硬件** 之间的桥梁

### 1.3 常见操作系统分类

| 领域        | 常见系统                        |
| ----------- | ------------------------------- |
| PC / 服务器 | Windows、Linux、macOS           |
| 移动端      | Android、iOS、鸿蒙（HarmonyOS） |

## 二、初识 Linux

### 2.1 Linux 是什么？

- **Linux** 本身只是一个**操作系统内核**（Kernel），负责管理硬件和提供系统调用。

- 我们常说的“Linux 系统”实际上是指 **Linux 内核 + GNU 工具集 + 桌面环境 + 应用软件** 组成的完整发行版。

  GNU 工具集是什么？**GNU全称是"GNU's Not Unix"** ，是计算机史上最著名的一个"递归缩写"，一套开源命令全家桶，包含 Shell、编译器、文件操作、文本处理等几百个工具。

  这就涉及到一个经典的历史故事：

  - 1991年，林纳斯·托瓦兹（Linus Torvalds）写出了 **Linux 内核**（发动机）。
  - 但是，一个发动机没法开车。碰巧，有一个叫 **GNU** 的组织，早在80年代就写好了全套“方向盘、油门、刹车”（即 `bash`、`gcc`、`emacs` 等工具），唯独没写出自己的“发动机”（他们的 Hurd 内核迟迟没做出来）。

  于是，林纳斯把 Linux 内核和 GNU 工具集一结合，一个完整的操作系统就诞生了！

  **严谨的学术圈至今坚持管它叫“GNU/Linux 系统”**，就是为了纪念 GNU 组织贡献的那些不可或缺的工具集。而我们平时为了方便，就简称“Linux 系统”了。

### 2.2 常见 Linux 发行版（Distros）

- **Ubuntu**（新手友好）
- **CentOS / RHEL**（企业服务器常用）
- **Debian**（稳定版）
- **Fedora**（新技术先行）
- **Arch Linux**（高度可定制）
- **Kali Linux**（安全渗透测试）

### 2.3 Linux 系统的四层结构c

```
┌─────────────────────────────────────┐
│         应用程序 (Apps)              │  ← 用户直接使用的软件（浏览器、编辑器、游戏）
├─────────────────────────────────────┤
│        Shell（命令行解释器）         │  ← 用户输入命令的界面（bash、zsh）
├─────────────────────────────────────┤
│        文件系统 (Filesystem)         │  ← 数据如何存储和组织（ext4、xfs）
├─────────────────────────────────────┤
│        Linux 内核 (Kernel)           │  ← 驱动硬件、调度进程、管理内存，
└─────────────────────────────────────┘
```

> **Linux 应用程序**是运行在 Linux 系统上的软件，用于完成特定任务或提供特定功能，包括桌面工具、开发软件、系统管理工具和嵌入式应用等。
>
> **Shell** 是一种命令语言解释器，它为用户提供了一个与操作系统内核交互的接口。用户通过 Shell 输入命令，Shell 将这些命令翻译成计算机可以理解的二进制代码，并传递给内核执行。执行完毕后，Shell 再将结果翻译回用户可以理解的形式。
>
> **文件系统**（Filesystem） 是一种用于管理和组织存储设备上数据的方法。它定义了数据的存储结构、访问方式以及文件和目录的管理规则。文件系统是Linux操作系统的核心组成部分，直接影响数据的存储、管理和访问效率。
>
> Linux支持多种文件系统，每种都有其独特的特性和用途：
>
> 1. **ext2/ext3/ext4**：最常用的文件系统类型，其中ext4性能更优，支持更大的存储容量。
>
> 2. **XFS**：高性能文件系统，适合处理大数据和高并发操作。
>
> 3. **Btrfs**：支持快照、动态卷管理和数据完整性检查。
>
> 4. **FAT32/NTFS**：与Windows兼容，常用于USB设备和可移动存储。
>
> 5. **ReiserFS**：以高效存储小文件和快速目录操作而闻名。
>
> 6. **JFS**：由IBM开发，适合大型文件系统。
>
> 7. **tmpfs**：基于内存的文件系统，适用于存储临时文件。
>
>    ​
>
> **Linux内核**是Linux操作系统的核心组件，负责管理计算机的硬件资源，并为用户空间程序提供系统调用接口。它是一个开源的模块化内核，最早由芬兰计算机科学家Linus Torvalds于1991年创建，基于Unix设计思想，具有稳定性、安全性和高效性。

### 2.4 Shell 的本质（核心定义）

Shell 是一个**命令行解释器（Command-Line Interpreter）**

**类比编程语言里的解释器**

| 维度           | **Shell**                              | **Python 解释器**                  | **JavaScript 引擎**                   |
| -------------- | -------------------------------------- | ---------------------------------- | ------------------------------------- |
| **是什么**     | 命令行解释器                           | Python 语言解释器                  | JS 语言解释器（如 V8）                |
| **输入什么**   | 你敲的命令（如 `ls -l`）               | `.py` 脚本文件或交互式代码         | `.js` 脚本文件                        |
| **干什么活**   | 读取输入 → 解析语法 → 调用系统内核执行 | 读取代码 → 解析语法 → 执行逻辑运算 | 读取代码 → 解析语法 → 操作浏览器 DOM  |
| **谁来执行**   | 调用 Linux 内核（Kernel）干活          | 调用操作系统和 CPU 干活            | 调用浏览器渲染引擎和操作系统干活      |
| **常见“品种”** | bash、zsh、fish、sh                    | CPython、PyPy                      | V8（Chrome）、SpiderMonkey（Firefox） |

**结论**：就像 `Python` 这个词既指语言，也通常指那个叫 `python3` 的解释器程序一样，`Shell` 这个词既指命令行这种交互方式，也泛指那一类叫 `bash`、`zsh` 的解释器程序。



**Shell 有"很多种"，不是只有一个**

就像"浏览器"有 Chrome、Firefox、Edge 一样，**Shell 也有很多种不同的实现**，它们功能略有差异，但核心都是"命令行解释器"。

| Shell 名称     | 特点                                   | 是否常用                      |
| -------------- | -------------------------------------- | ----------------------------- |
| **bash**       | Linux 最主流、默认的 Shell，功能强大   | ✅ 绝大多数 Linux 默认         |
| **zsh**        | bash 的增强版，补全和主题更丰富        | ✅ 很多开发者爱用（Oh My Zsh） |
| **sh**         | 最原始的 Shell，功能最少，但兼容性最好 | 脚本编写时常用                |
| **fish**       | 对新手最友好，自动提示很智能           | 小众但好用                    |
| **csh / tcsh** | 语法类似 C 语言                        | 较少用                        |

你可以用下面的命令查看当前系统有哪些 Shell：

shell

```
cat /etc/shells
```

查看当前你正在用的是哪个：

shell

```
echo $SHELL   # 输出类似于 /bin/bash
```

## 三、Linux 命令行入门

### 3.1 命令的基本格式

shell

```
命令名 [选项] [参数]
```

- **命令名**：要执行的操作（如 `ls`）

- **选项**：调整行为（如 `-l` 表示详细信息）

  -用来声明「选项（参数 / 开关）」

- **参数**：操作对象（如文件名或路径）

示例：

shell

```
ls -l /home
```

> 命令名 `ls`，选项 `-l`，参数 `/home`
>
> `-l` = long（长格式）,让ls不以简洁列表展示，而是输出详细信息
>
> 含义：以详细列表形式显示 `/home` 目录下的内容

> ⚠️ `rm -rf /` 会删除整个系统，务必小心使用。
>
> Linux 约定：所有普通用户的个人数据、桌面、下载、自建文件夹（图里的 Desktop、test、pwntools 这些），全部收纳在/home/用户名内；/home是存放所有用户家目录的顶层文件夹，每个用户独占一个子文件夹，用来隔离不同用户的文件，避免互相篡改、越权访问。
> 当你用账号pwn登录系统，操作系统就会把/home/pwn设为你的默认起始目录。
>
> 路径 `/home/pwn/Desktop` 每一段含义：
>
> 1. `/`：Linux 系统最顶层的根目录
>
> 2. `/home`：专门存放所有普通用户个人文件夹的系统目录
>
> 3. **pwn：你的登录用户名**，系统为这个用户单独创建专属家目录`/home/pwn`，你的桌面、下载、代码文件夹都存放在这里，用来隔离不同用户的文件权限
>
> 4. `Desktop`：桌面文件夹，属于用户`pwn`家目录内部的子目录，完整绝对路径就是`/home/pwn/Desktop`
>
> 5. 顶层结构
>
>    ```
>    /  # Linux根目录，系统最顶层
>    └── home
>        └── pwn  # 用户pwn的家目录，也就是你文件管理器当前打开的Home，终端~就等价于这个目录
>            ├── Desktop         # 桌面，绝对路径 /home/pwn/Desktop
>            ├── Documents       # 文档，绝对路径 /home/pwn/Documents
>            ├── Downloads       # 下载，绝对路径 /home/pwn/Downloads
>            ├── Music           # 音乐，绝对路径 /home/pwn/Music
>            ├── Pictures        # 图片，绝对路径 /home/pwn/Pictures
>            ├── Public          # 公共共享，绝对路径 /home/pwn/Public
>            ├── PWN             # 你手动新建的文件夹，绝对路径 /home/pwn/PWN
>            ├── pwntools        # 工具目录，绝对路径 /home/pwn/pwntools
>            ├── snap            # snap软件包目录，系统自动生成，绝对路径 /home/pwn/snap
>            ├── Templates       # 模板目录，绝对路径 /home/pwn/Templates
>            ├── test            # 测试目录，绝对路径 /home/pwn/test

## 五、Linux 权限管控（核心安全机制）

### 5.1 用户分类

| 用户类型               | 说明                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **root**（超级管理员） | 拥有最高权限，可操作系统任何文件，日常**禁止直接使用 root 登录** |
| **普通用户**           | 仅对自己家目录（`/home/用户名/`）有完全控制权                |
| **系统用户**           | 用于运行系统服务（如 `nobody`、`www-data`），通常无法登录    |

- 查看当前用户：`whoami`
- 切换用户：`su  - 用户名`（切换到其他用户），`su`（直接切换到 root）
- 临时提权执行单条命令：`sudo 命令`

------

### 5.2 文件的三层权限模型

一，每个文件/目录针对三类用户分别设置权限：

| 身份标识       | 含义                                                         |
| -------------- | ------------------------------------------------------------ |
| **u**（user）  | 文件拥有者                                                   |
| **g**（group） | 文件所属用户组（默认用你的主组pwn，也就是这个文件归属pwn用户组；后续只要别的用户被加入pwn组，就能获得该文件组权限规定的访问能力。） |
| **o**（other） | 其他所有用户                                                 |
| **a**（all）   | 以上三者之和                                                 |

**常见命令**

```shell
whoami                # 查看当前登录用户名
su                    # 切换用户（默认切换root，需要root密码）
su - 用户名           # 完整切换用户（加载用户环境变量）
groups                # 查看当前用户所属附属组
id                    # 查看用户uid、gid、所有所属组
adduser zhangsan      # Ubuntu交互式创建新用户（自带创建家目录、提示设置密码）
cat [文件]            # 读取文件内容
ls /                  # 列出根目录下文件
ls -lah [文件]        # 长列表、显示隐藏文件、人性化大小
sudo usermod -aG [组] [用户]  # 将用户追加加入附属组
exit                  # 退出当前shell会话
id -u 用户名          # 获取用户UID
id -G 用户名          # 获取用户所有组ID（数字）
id -nG 用户名         # 获取用户所有组名称
```

二、涉及核心知识点

1. **`su` 和 `su -` 区别**

- `su 用户名`：只切换身份，**不加载目标用户环境变量**
- `su - 用户名`：完整登录，加载 `.bashrc/.profile`，推荐使用

> ```shell
> su - zhangsan
> ```
>
> adduser 创建用户后设置登录密码，输入密码错误就会 Authentication failure

- `su` 需要**目标用户密码**
- `sudo` 需要**当前用户自身密码**（前提：当前用户在 sudo 组）

2. **用户与组基础概念**

- /etc/passwd :所有用户信息库，所有用户可读，存储 uid/gid、家目录、登录 shell

  格式示例：

  ```shell
  zhangsan:x:1002:1002:,,,:/home/zhangsan:/bin/bash
  ```

  x代表密码不存这里，转移到 /etc/shadow

- /etc/shadow：用户加密密码文件，权限 -rw-r----- root:shadow

  默认只有 root、shadow组成员才能读取！普通用户直接cat /etc/shadow权限拒绝。

uid/gid 含义

- uid：用户 ID；gid：用户初始主组
- 主组：创建文件默认归属组；附属组：附加权限组

```shell
id 输出：uid=1002(zhangsan) gid=1002(zhangsan) groups=1002(zhangsan),42(shadow),100(users)
```

3. **用户添加附属组：`usermod -aG`**

⚠️ 重点易错点：

- `-G`：附属组；`-a` append 追加！**不加 -a 会覆盖原有附属组！**

```shell
sudo usermod -aG shadow zhangsan
```

执行完成后**必须重新登录用户（exit 重进 su）**，组权限才生效！

> 你第一次执行完立刻切换 zhangsan，组没刷新，依旧无法读取 shadow；重新登录后生效。

4. **文件权限模型（/etc/shadow 案例）**

```
-rw-r----- 1 root shadow /etc/shadow
```

- 属主：root（读写）

- 属组：shadow（只读）

- 其他人：无任何权限

  所以：普通用户不在 shadow 组 → cat 被拒绝,用户加入 shadow 附属组 → 获得读取 shadow 权限（安全风险！渗透常关注这点）

5. **adduser 与 useradd 区别（Ubuntu 特有）**

- `adduser`：perl 封装的交互式工具，自动创建家目录、创建同名主组、提示设置密码（你使用的这个）
- `useradd`：底层原始命令，默认**不创建家目录、不设置密码**，需要额外参数

6. **WSL Ubuntu 环境特点**

WSL2 的 Ubuntu 和真机 Linux 用户管理逻辑一致，但默认没有启用 root 密码：

```
su（不加用户名）默认切root，你一开始su失败：WSL默认root未设置密码！
想要su切换root两种方案：
1. sudo passwd root 设置root密码
2. sudo -i 直接免密进入root（推荐WSL）
```









### 5.3 三种基础权限及数字表示

| 权限 | 字符 | 数字值 | 对文件的作用  | 对目录的作用             |
| ---- | ---- | ------ | ------------- | ------------------------ |
| 读   | r    | 4      | 查看文件内容  | 列出目录内文件名（`ls`） |
| 写   | w    | 2      | 修改文件内容  | 增删或重命名目录内文件   |
| 执行 | x    | 1      | 运行程序/脚本 | 进入目录（`cd`）         |

因为权限在计算机底层是用**二进制位（bit）**来存储的，每个权限占 1 个 bit 位：

位置编号”本身是人为定义的（约定俗成）

位置编号：2      1       0
          ┌───┬───┬───┐
          │ r      │  w   │   x    │  ← 我们规定：这个位置放什么权限
          └───┴───┴───┘

| 权限     | 二进制位 | 权值（2 的幂） |
| -------- | -------- | -------------- |
| 读 (r)   | 第 2 位  | 2² = **4**     |
| 写 (w)   | 第 1 位  | 2¹ = **2**     |
| 执行 (x) | 第 0 位  | 2⁰ = **1**     |

权限的数字值（4、2、1）不是字节数，它们是权重位（bit 位权），是为了方便用二进制或八进制表示权限而人为规定的权值。

**权限组合数字计算**：

- `rwx` = 4+2+1 = **7**
- `rw-` = 4+2+0 = **6**
- `r-x` = 4+0+1 = **5**
- `r--` = 4+0+0 = **4**
- `---` = 0

### 5.4 修改权限：`chmod`

**数字法**（最常用）：

shell

```
chmod 755 script.sh      # 所有者 rwx(7)，组 r-x(5)，其他人 r-x(5)
chmod 600 secret.txt     # 只有所有者可读写(6)，其他人无权限(0)
```

**符号法**（更直观）：

shell

```
chmod u+x script.sh      # 给所有者增加执行权限
chmod g-w secret.txt     # 移除所属组的写权限
chmod a+r file.txt       # 给所有用户增加读权限
```

**chmod 权限参数**

| 参数      | 全称      | 含义                                                         |
| --------- | --------- | ------------------------------------------------------------ |
| `+x`/`-x` | execute   | `+x`增加执行权限，`-x`移除执行权限；x 权限用于运行脚本、可执行程序 |
| `+r`/`-r` | read      | 增加 / 移除读取权限                                          |
| `+w`/`-w` | write     | 增加 / 移除写入权限                                          |
| `-R`      | recursive | 递归修改目录及其内部所有文件权限                             |

----------------------------------------------------------------------------

### 5.5 修改拥有者：`chown`（change owner）

shell

```
chown bob file.txt                 # 将文件所有者改为 bob
chown bob:techgroup file.txt       # 将所有者改为 bob，所属组改为 techgroup，:：分隔用户名、用户组，                                      固定格式；冒号前是用户，冒号后是用户组
chown -R bob /data/project/        # 递归修改整个目录及其内容
```

**chown 文件归属参数**

| 参数 | 全称      | 含义                                                    |
| ---- | --------- | ------------------------------------------------------- |
| `-R` | recursive | 递归修改目录、内部所有子文件 / 子目录的所属用户、所属组 |

### 5.6 特殊权限（简要了解）

| 权限       | 作用                                            |
| ---------- | ----------------------------------------------- |
| **SUID**   | 程序运行时临时获得其所有者的权限（如 `passwd`） |
| **SGID**   | 目录内新建文件自动继承目录所属组                |
| **Sticky** | 共享目录下只能删除自己的文件（如 `/tmp`）       |

### 5.7 `sudo` 提权机制

- `sudo` 允许**普通用户临时以 root 权限执行单条命令**，避免直接使用 root 账号。
- 配置文件：`/etc/sudoers`（需用 `visudo` 编辑）

**常用参数**：

shell

```
sudo -u 用户名 命令    # 以指定用户身份执行
sudo -u ubuntu touch testfile.txt       #用 ubuntu 身份创建文件····
sudo -i               # 切换到 root 环境（持续提权，慎用）
```

> ✅ 安全原则：能用 `sudo` 就别直接切 root，遵循**最小权限原则**。

### 6.3 查找大文件并清理

shell

```
find / -type f -size +1G -exec ls -lh {} \;   # 查找大于 1GB 的文件
```

**find 查找命令参数**

| 参数    | 全称    | 含义                                           |
| ------- | ------- | ---------------------------------------------- |
| `-type` | type    | 限定文件类型，`-type f`普通文件、`-type d`目录 |
| `-size` | size    | 按文件大小筛选，`+1G`大于 1G，`-1G`小于 1G     |
| `-exec` | execute | 对匹配结果批量执行后续 shell 命令              |

**find /**：从根目录/开始遍历整个文件系统搜索文件；
**-size +1G**：筛选文件大小大于 1GB，+代表大于，-代表小于，无符号代表等于；单位G是吉字节；
**-exec 命令 {} \;**：find 的执行动作语法，把搜索得到的每一个文件，逐个传给后面的命令执行：
**{} **占位符，会被逐个替换成匹配到的文件完整路径；
**\; **是-exec语法必需的结束标记，反斜杠用来转义分号，避免 shell 提前解析分号；
**ls -lh**：列出文件详情，-l长格式展示权限、所有者、大小等信息；-h把文件大小转为人类易读单位（GB、MB），不再输出原始字节数。

### 6.4 打包压缩与远程传输

shell

```shell
tar -czvf backup.tar.gz /home/user/data/      # 压缩
scp backup.tar.gz user@远程IP:/backup/        # 传输到远程服务器
```

**tar 压缩解压高频参数**

| 参数 | 全称    | 含义                                     |
| ---- | ------- | ---------------------------------------- |
| `-c` | create  | 创建新的压缩归档包                       |
| `-x` | extract | 解压、提取归档内文件                     |
| `-z` | gzip    | 采用 gzip 算法，处理`.tar.gz`格式        |
| `-v` | verbose | 详细模式，打印每一个被处理的文件名       |
| `-f` | file    | 后接压缩包文件名，必须放在所有短参数末尾 |
| `-j` | bzip2   | 采用 bzip2 算法，处理`.tar.bz2`格式      |

**tar -czvf backup.tar.gz /home/user/data/ 整体作用**
把 /home/user/data/ 目录下所有文件、子目录打包并压缩为 backup.tar.gz，压缩包生成在当前执行命令的目录。

backup.tar.gz：输出的压缩包名称
/home/user/data/：需要打包压缩的源目录

**scp backup.tar.gz user@远程IP:/backup/整体作用**
将本地生成的压缩包 backup.tar.gz，通过加密 SSH 通道上传到远程服务器的 /backup/ 目录下

scp：secure copy，基于 SSH 加密协议的远程文件传输工具，传输全程加密
backup.tar.gz：本地要上传的文件
user@远程IP：远程服务器登录账号与 IP 地址
user：远程机器的用户名
远程IP：远程服务器公网 / 内网 IP
:/backup/：远程服务器上的目标存放目录（远程机器 /backup 文件夹）

**scp 远程传输参数**

表格

| 参数 | 全称                            | 含义                                   |
| ---- | ------------------------------- | -------------------------------------- |
| `-r` | recursive（递归的、循环遍历的） | 递归传输整个目录，传输文件夹必须加`-r` |

## 七、常见问题速查

| 问题                 | 解决方法                                            |
| -------------------- | --------------------------------------------------- |
| 忘记普通用户密码     | root 用户（sudo -i）用 `passwd 用户名` 重置         |
| 文件无法执行         | `chmod +x 文件名`                                   |
| 没有权限编辑系统文件 | 使用 `sudo vim 文件路径`                            |
| 端口被占用           | `netstat -tlnp | grep 端口号`，然后 `kill` 对应 PID |
| 磁盘空间不足         | `df -h` 查看使用率，`du -sh *` 定位大文件夹         |

**df**=disk free,查看磁盘分区的使用情况：各分区总容量、已用空间、剩余空间、使用率、挂载点；

**du**：disk usage，统计目录 / 文件实际占用磁盘空间大小

**netstat **是 Linux 网络状态查看工具

netstat/ss 网络类

| 参数 | 全称    | 含义                                                         |
| ---- | ------- | ------------------------------------------------------------ |
| `-t` | tcp     | 仅展示 TCP 协议端口、连接，过滤 UDP 等其他协议               |
| `-l` | listen  | 只列出处于监听 LISTEN 状态的端口（对外提供服务的端口）       |
| `-n` | numeric | 数字格式输出，不解析域名、服务名，直接展示 IP、端口数值，查询提速 |
| `-p` | program | 展示占用端口的进程 PID、程序名，需要 sudo 权限               |

netstat -tlnp执行后，会输出本机所有 TCP 监听端口、对应进程的完整列表。管道符把netstat输出的所有结果，传递给后面的grep做筛选。筛选出内容里包含目标端口的行，只保留该端口对应的监听条目，过滤其余无关端口信息。
